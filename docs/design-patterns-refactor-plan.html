How to use this tracker

  1. Read this file before starting refactor work: docs/design-patterns-refactor-plan.html
  2. Do all refactor work on the long-lived branch refactor/design-patterns (create from main if it does not exist). Do not commit refactor changes directly to main.
  3. For each PR in the checklist, branch from refactor/design-patterns using refactor/design-patterns/pr-NN-short-name, then open a PR into refactor/design-patterns (not main) until the epic is complete.
  4. Pick the first unchecked PR in the PR checklist below (or the phase marked active).
  5. Follow architecture rules: domain in packages/core/, thin UI, ports/adapters in src/services/.
  6. One PR per checklist item when possible; keep useAuth, useModal, useGameLogic APIs stable until noted.
  7. After merging, check the PR box, add evidence in handoff notes, and commit this HTML if notes changed.
  8. Related docs: architecture.mdc, systemPatterns.md, codebase optimization tracker

Progress is stored in localStorage key qwordly-design-patterns-refactor-v1 (per browser). Agents: paste exported JSON into PR description or memory-bank when handoff is needed.

Goals

  • Apply named design patterns at boundaries where complexity lives today.
  • Move framework-agnostic logic into packages/core/.
  • Keep UI components thin; shrink orchestration-heavy modules.
  • No big-bang — each PR leaves the app runnable with tests green.
  • Keep refactor work off main until the epic branch is ready to merge.
