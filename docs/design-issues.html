Testability And Evidence Notes

  • Animated reward, profile, hint, and achievement states can make uiautomator dump return ERROR: could not get idle state. Use screenshot and logcat evidence for animated states, then rerun XML capture after the UI settles when possible.
  • Do not run overlapping uiautomator dump sessions. The 389-credits-website-after-craig-tap-logcat.txt crash was investigated and traced to Android's shell com.android.commands.uiautomator.Launcher process (uid 2000) throwing UiAutomationService ... already registered after two dump sessions overlapped. It is a harness artifact, not a com.roobsworld.riddlequest crash, and future captures should serialize UI dumps before treating logcat as app evidence.
  • Legal-link automation drift was not counted as a pass. Spanish, Japanese, and Arabic retries were captured only after verifying the expected About/Legal surface was visible again.
  • The Expo Dev Client Tools overlay can intercept taps in the app header. For dev-client coordinate tests, turn off the Tools button before tapping the coin balance; otherwise the overlay hit area can open the Expo dev menu even when the app's coins-display-touchable node is present underneath.
  • The first dev-client server-selection attempt exited after Google Play Services forced a measurement module restart. Relaunch recovered successfully, so this is tracked as runtime evidence rather than a Qwordly crash.
  • Google Play / Play Store background package installs can terminate the app during matrix runs when they stop com.google.android.gms. The matrix runner now guards this by disabling com.android.vending only for the duration of each emulator target and restoring it afterward; do not treat a launcher screenshot after installPackageLI as a passed or ignored UI check.
