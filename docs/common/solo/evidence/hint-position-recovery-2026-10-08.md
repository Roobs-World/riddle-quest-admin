# Recovery from invalid hint positions

Hint operation data is intentionally unknown in the generic bridge envelope. The previous handler admitted fractional and negative positions, and the reducer accepted fractional/NaN positions. A fractional confirmed hint selected a non-integer slot and stored a phantom hint lock. In the real rendered game, subsequent physical typing left the visible answer empty instead of İZMİR. Eight original unit failures and the rendered failure are retained.

The operation handler now requires an integer hint position within the current question and an existing revealed letter. Invalid metadata rolls back the provisional hint and uses the existing generic error notice rather than presenting it as a completed grant. Both provisional and confirmed reducer paths independently reject non-integer or out-of-bounds positions. Invalid confirmations retire their provisional reveal and restore ordinary selection and typing. No server grants or persisted receipts are changed.
