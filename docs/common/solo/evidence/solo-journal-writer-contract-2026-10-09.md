# Per-owner journal writer contract checkpoint

The previous rendered audit proves passive draft persistence can remove another tab's required paid request with either an active or released lease. Tracing the recovery hook finds the same unguarded read/write/clear adapter across reconciliation, successor append, draft persistence, answer queueing and settlement, rejection cleanup, preview admission and coin-action enqueueing. A lease-only patch to the draft effect would leave stale snapshots unsafe after release or expiry and would not protect other writers.

Two designs were considered: explicit expected bytes at each of the thirteen mutation sites, or a private observation cursor owned by a bound adapter. The latter centralizes the immutable predecessor and keeps callers from incorrectly capturing already-mutated journal objects. `journalWriter.ts` implements that contract without changing gameplay yet.

Each mounted writer has its own observed-byte cache. Reads validate a captured value without a second live read. Writes and deletion check account/lifetime admission, compare the actual record to the observed predecessor, acquire the genuine lease and recheck the predecessor before mutation. Write and delete results are verified before advancing the cursor. A separately guarded receipt transition can acknowledge only the exact record it actually persisted. Another reader cannot refresh this writer's cursor merely by inspecting shared storage.

Eight concrete-adapter tests pass: active takeover, released takeover, expired takeover, ordinary edit, failed write with recovery, failed deletion with recovery, retired owner and unknown nonempty predecessor. Tests confirm both writes and deletion preserve another tab's new paid request. The type check and TSDoc audit pass (27,887 declarations across 1,228 files). Logs and source hashes are in `artifacts/solo-journal-writer-contract-2026-10-09/`. All jobs are terminal.

Integration remains required. The gameplay hook still uses the old adapter and the original rendered failure remains unfixed. Each committed hook lifetime must receive a distinct writer; standalone test/setup adapters and another tab must retain independent observation cursors. The deferred receipt path must acknowledge only its actually saved result without adopting an unrelated replacement. Startup initialization must keep durable-write-before-preview ordering and the current direct-guess fallback coherent. A conflicted write must not clear the foreign record or leave mutated in-memory queues mistaken for durable work. Re-run the rendered active/released takeover probes, current recovery cases, all target builds and startup checks before handoff.

The localStorage checks are cooperative guards, not an atomic database transaction against a process bypassing the lease protocol. No deployment, commit, push or completed gameplay-fix claim is made. The broader goal remains active.
