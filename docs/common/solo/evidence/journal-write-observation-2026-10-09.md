# Durable journal write investigation, 9 October 2026

The injected real reducer/router/journal browser harness confirms one redundant synchronous journal write on Continue request admission. At both 390px and 1280px, in development and production React, Continue writes the exact same 1880-byte JSON twice, retaining the same request ID. This is four reproduced duplicate writes across 16 gameplay journeys (four actions × two viewports × two React modes). All 96 existing request ownership, lease, durable journal and browser-error assertions passed.

The other actions do not support broad duplicate suppression. Guess writes 1251 then 1265 bytes because its empty draft representation changes. Hint writes 1160 then 1161 bytes because cursor state changes. Skip writes once (1069 bytes). The probe records exact serialized payloads before delegating to the existing real storage adapter. Its extra serialization means it is work-count evidence, not a timing benchmark. These fixed payload sizes do not describe every real account or buffered journal.

The provisional recovery draft effect depends on guessPending as well as draft cells and cursor. It updates the mutable journal and calls its writer even when the admitted Continue request already persisted the same draft. However, simply returning when that in-memory draft matches would be unsafe: the same effect mutates the journal before knowing whether a write succeeded, and future effect delivery may be the opportunity to retry a failed draft checkpoint. Any optimization must distinguish successful persistence from current mutable state, preserve changed cursor/letter writes, and retain admission-before-request delivery. No production optimization is claimed or applied in this investigation.

Evidence is in `artifacts/journal-write-observation-2026-10-09`: exact probe source derived from the pending-play lifetime harness, immutable write payload traces, summaries, screenshots, separate React-mode logs and observed source hashes. The held authority response and controlled renewal clock test request durability; no real economy grant, storage failure sequence or end-to-end input timing was tested here. Both browser jobs exited zero and the harness finally blocks closed contexts, browsers, HTTP servers and owned scratch builds. No client artifacts or provider data changed.
