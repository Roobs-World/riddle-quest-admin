# Additional release targets — round 6

Research date: 21 September 2026. This round reviews destinations beyond the 43 canonical targets in `config/platform-monetization.json`. Sources are first-party developer or platform documentation. Candidates must accept an externally hosted standard HTML5/Vite application, have active external-developer intake, avoid native or proprietary-runtime conversion, and have no published mandatory exclusivity requirement.

Only two additions are defensible: **Pi Apps Platform** and **MiniPay Mini Apps**. Both load a developer-hosted HTTPS web application and expose optional JavaScript/browser APIs. Their listing workflows do not require transferring the game or withdrawing it from other platforms. The authenticated terms must still be reviewed before submission because the complete developer agreements are presented during account onboarding.

## Integration boundaries

- Build each candidate as an isolated target. Pi SDK, MiniPay wallet code, Celo libraries, ads, authentication, and payment code must never enter Jest, Facebook, Reddit, YouTube, Netflix, or Yahoo artifacts.
- Preserve the normal solar-system game presentation. Platform integration belongs behind adapters and must not replace the shared game UI.
- Pi identity and payments require backend verification. Store purchase attempts and grants with provider transaction IDs so repeated approval/completion callbacks cannot duplicate an entitlement.
- MiniPay wallet connection must be target-only. The game should continue to function without commerce, and a rejected, reverted, or unconfirmed transaction must never grant an item.
- Neither target should be counted as published until its authenticated directory/listing approval is captured. A working hosted URL or testnet application is development evidence only.

## Automation boundary

### Pi Apps Platform

Automation can build and audit the isolated artifact, deploy its HTTPS URL, expose the domain validation file, configure target metadata from a checked-in manifest, test the SDK sandbox, verify backend identity/payment routes, and record evidence in the dashboard. A human must create the Pi account in Pi Browser, complete email verification and KYC, accept the developer terms, create Testnet/Mainnet projects and wallets, protect the API key and wallet secret, request Ecosystem listing, and approve any real-currency/tax decision. No public listing API was found.

### MiniPay Mini Apps

Automation can produce the hosted target, network-origin manifest, icons, listing copy, legal links, PageSpeed report, wallet-detection tests, and dashboard evidence. A human must review and accept the submission terms, open the listing account/form, decide whether cryptocurrency commerce is appropriate, provide any business/KYC details requested, and submit the listing. The documented intake is a form rather than a release API.

## Exclusions

- **VK Mini Apps:** it is technically a hosted Vite-compatible web platform, but the current official material did not establish that a UK company can complete contracting and receive advertising or commerce payouts. The reviewed public documentation also did not provide sufficiently clear non-exclusive commercial terms. Revisit only after written UK eligibility and payout confirmation.
- **OK Games / Odnoklassniki:** the official API accepts hosted HTML5 and requires OK payments and/or advertising, but UK contracting and payout access could not be verified. Its Russia-linked commercial route and authenticated agreement introduce sanctions and payment risk. It is not a defensible UK release target in this round.
- **VK Play browser games:** first-party documents show browser-game applications, but the relationship between VK Play, vk.com Games and Odnoklassniki distribution is not clear enough to establish a distinct direct destination, current UK intake, and non-exclusive terms.
- **Vewd / Opera TV Store:** no current first-party self-service submission route with active external intake and clear licensing terms was verified. Historical documentation is insufficient.
- **Samsung Tizen TV, LG webOS TV and VIDAA:** these use web technologies but require platform-specific TV packages, signing tools, manifests, device SDKs, or partner onboarding. They fail the standard hosted HTML5/Vite-artifact requirement for this round.
- **WeChat Mini Games, Alipay Mini Programs and Douyin Mini Games:** they require proprietary mini-program runtimes/toolchains and regional business onboarding rather than an unchanged hosted Vite application.
- **OKONA ONLINE:** its first-party portal accepts HTML5 folders and exposes release automation, but the service is specifically designed for shared-screen games controlled by players' phones. Riddle Quest does not implement that multiplayer/controller interaction, so this is not a credible destination for the current game.
- **Apple Mini Apps Partner Program:** the programme is for native App Store host applications that distribute mini apps. It requires an iOS/iPadOS host binary and Apple commerce APIs, conflicting with the repository's browser-only scope.
- **LinkedIn Games, Bing Games and Microsoft Start Games:** no open first-party external-developer submission route was verified; observed games appear partner-curated or supplied through existing distributors.
- **Base Mini Apps:** these use the Farcaster Mini App standard and would duplicate the already tracked Farcaster target rather than create an independent release artifact.
