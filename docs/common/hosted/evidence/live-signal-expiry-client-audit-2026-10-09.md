# Live signal expiry: client recovery audit — 2026-10-09

The existing client correctly handles a healthy private stream whose retained revision expires, then receives a fresh valid revision. No production change was needed. Null revision notifications disable push health, immediately request canonical reconciliation and restore the 500 ms fallback cadence. A later valid revision restores the five-second push watchdog while preserving the original SDK connection. The poll scheduler anchors deadlines to the last authoritative delivery, so repeated heartbeat callbacks do not indefinitely postpone reconciliation.

Twelve injected React browser journeys passed with 240 assertions: Chromium and cached Firefox 153, development Strict Mode and production React, at 390×568, 390×844 and 1280×844. Each journey proves fallback performs a poll, expiry never submits a gameplay command, recovery admits one new revision, subsequent player input advances once, parent updates retain the stream, and retirement aborts transport and leaves the seat once. No browser errors or unhandled rejections occurred.

The artifact-local harness `artifacts/live-signal-expiry-client-audit-2026-10-09/verify-browser.mjs` derives from the existing watchdog harness and adds a controlled valid → null → fresh revision sequence. It uses the real `LiveRaceGame`, observer and signal hook. Firebase SDK transport is injected; stream watchdog/backoff deadlines are accelerated and synthetic heartbeats arrive every 50 ms. Production polling intervals are unchanged. These results do not measure real provider latency, deployed performance or the native Firefox MCP browser. Browser contexts, local servers and owned scratch directories are released by the harness `finally` path; all four run handles exited successfully.

Logs, per-journey assertions, screenshots and `summary.json` are retained beside the harness.
