# Live race close and retired-seat recovery

Closing a live game before its join returned could expose a new start while the old request still owned a server seat. Cleanup after close or account/provider retirement also sent one leave request and swallowed a failed delivery. Real mounted-browser probes reproduced both failures before the corresponding fixes.

`LiveRaceGame` now retains an unresolved join after close, queues leave for its eventual ticket, and returns to the intro after the authority accepts that leave. Failed leave remains retryable under the same ticket and request ID. A same-provider subsequent start therefore follows cancellation rather than recovering the ticket that old cleanup is about to retire. Definitively rejected joins still permit immediate dismissal while an optional invitation preview read remains pending; this preserves cancellation of read-only confirmation work.

Detached cleanup captures the original target transport method and leave ID. Duplicate unmount, late join and late poll observations share one job per original ticket. A failed request gets up to three retries with 1/2/4-second backoffs and ten-second command deadlines. A matching, validated terminal receipt releases retry waits and newer local deadlines, including when the receipt arrives late. An already completed owner run also stops cleanup while preserving the rival's finish opportunity. Definitive authority rejection stops retries. Exhaustion leaves a deduplication marker and no timer or abort listener; the underlying SDK's server mutation is not represented as cancelled.

No client economy, scoring, identity authority, locale copy or provider SDK changes were made. Retry requests still go through the original target adapter and server ownership checks. The current live-path SDK ownership and idempotent cancellation audit is recorded separately in `docs/common/hosted/evidence/race-invitation-creator-recovery-2026-10-05.md`.

Backend and core bytes are unchanged, including 24 compiled/installed core hashes. Earlier 1,722 backend unit tests, 641 SDK cases and the four fresh creator SDK cases are reused evidence, not new full-suite runs.

## Limits and continuation

These injected transport failures demonstrate component behavior; they do not measure production network latency or outage rates. Detached recovery is finite: four never-settling requests can consume at most 47 seconds of local waiting. A longer outage can exhaust recovery. Active visible close continues using the existing retry presentation. Native Firefox was driven through Playwright; the earlier Firefox MCP information probe failed and supplied no observation.

Artifacts are retained under `artifacts/live-retired-leave-recovery-2026-10-05/`. `verify.py` checks current source hashes, red and green observations, fresh test logs, build bytes, cleanup, owned patch and terminal jobs. The retained recorded-race invitation API recovery issue remains unfixed and does not affect the mounted live controller. The overall improvement goal remains active.
