# Optional multiplayer proof blocks first input

A derived real React/reducer/local-transport browser harness compares reload with immediate immutable receipt proof and reload where that optional proof remains unresolved. At widths 390 / 1280, Chromium production reaches the usable board at 91.7 / 91.3 ms for immediate proof and 2376.8 / 2377.7 ms for unresolved proof. Firefox production measures 161.3 / 161.6 ms versus 2429.7 / 2436.9 ms. Both engines pass four journeys / 46 checks. Measurements include local reload, fixture intro click and first visible board; they are controlled local UI timings, not cloud/network measurements. The unresolved cases prove a canonical question has arrived while the board remains absent. No production source changed in this audit.

The first acceptance path currently awaits optional proof before applying the authoritative view. The dedicated proof cancellation added for close fixes exit latency, but initial gameplay still waits. Merely reducing its deadline would improve appearance by dropping recoverable drafts sooner; that does not satisfy the combined reliability and playability goal.

## Proposed boundary

Apply the validated canonical seat promptly and continue the optional historical lookup separately. Preserve the immutable predecessor checkpoint while the initial draft remains untouched; the current save layout effect otherwise writes the empty newly rendered board and revokes proof. A late accepted proof may restore cells only for the same delivery lifetime, canonical ticket/run/question/attempt and unchanged local letter intent. New typing or a command must cancel the optional wait and preserve the newer input; it must also unblock the initial delivery bookkeeping so commands do not queue behind a two-second read. Focus/cursor selection alone should not silently discard recovered letters: preserve the explicit cursor while recovering proven cells and reconciling canonical hint locks.

Close, account retirement, proof timeout/rejection, unavailable storage, competing writer, malformed locator and consumed-word checks remain required. Proof still cannot alter guess history, score, rewards or server authority. A progressively shown board must not overwrite the retained checkpoint merely by rendering, and a late result must never overwrite typed input or revive a discarded question.
