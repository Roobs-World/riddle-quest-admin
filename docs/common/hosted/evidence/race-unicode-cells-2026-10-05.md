# Complete Unicode graphemes in race play — 5 October 2026

Race hints, preloaded hints, feedback and confirmed history now carry complete Unicode graphemes. Both recorded and live guess transports accept their NFC representation within a derived 384-unit budget, and canonical stored history and optional draft recovery use the same capacity. Original authored evaluation and private answer bytes remain bounded to 128 units and are not rewritten.

The actual shared runtime accepted `लक्ष्म्यां` as a valid two-slot guess and evaluation answer, but rejected its nine-unit conjunct in every hint/feedback/history cell. Real-SDK baseline tests also reproduced failures in evaluation preloads, hints, correct guesses, history and live matches. A second fixture demonstrated that 128 raw units can normalize to 254 units, which exceeded both the previous guess and draft bounds.

The normalized budget is derived from Unicode's guarantee that NFC expansion is at most three times the original code-unit length: 128 × 3 = 384. Both raw and normalized input are bounded before segmentation; output cells represent exactly one grapheme and retain their input bytes. [Unicode UAX #15, section 9](https://www.unicode.org/reports/tr15/#Detecting_Normalization_Forms). The shared policy lives in a leaf module used by recorded/live requests and response cells.

The storage history limit grows from 256 to 384 units so the server can reread its own accepted normalized guesses. The original run parser retains supported historical records and scoring history. Local drafts permit complete normalized cells within the total guess budget; their bounded serialized record limit grows to 8,192 units for escaped identifiers. Draft recovery checks separately normalized cells so composition across a boundary cannot disguise oversized restored input. Account, run, locale, question, attempt, retention and ownership checks remain authoritative.
