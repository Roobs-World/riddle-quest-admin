# Multiplayer history grapheme boundaries

Canonical history previously checked each cell in isolation. Two cells can individually contain one grapheme but merge when joined: `a` followed by a separate combining grave accent, or separate regional indicators forming one flag. Three regional indicators can also regroup across stored cell boundaries while retaining the same total grapheme count. That same-count case bypassed even known-answer scoring because the incorrect cell segmentation could still produce two red colors.

Snapshot validation now reconstructs the word, segments it with the shared NFC-aware grapheme function, and requires both the exact cell count and each normalized cell boundary to match. This structural requirement applies equally to modern and answer-free history, before ownership or checkpoint consumption. Valid decomposed characters within a single cell and complete flag cells remain accepted.
