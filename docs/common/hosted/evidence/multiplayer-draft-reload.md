# Multiplayer unsent input reload recovery

Reloading an active race resumed the authoritative run and puzzle but lost unsent letters and the selected input slot. The hosted Jest pathway chat independently observed this loss in creator and matched races. A production component harness reproduced it locally on the exact prior RaceSession source: the recovered source SHA-256 `fb4084521e3029e49c2fd2fab4afacf67a86e3e83b7850740306b451cba1133a` matches the earlier source baseline. The corrected negative browser run failed after reload with five empty slots rather than the previously entered `P`, `I`. This baseline is retained under artifacts rather than inferred from the current Git HEAD, which does not contain the intervening shared multiplayer improvements.

`RaceDrafts` stores a single bounded presentation record separately from the run pointer. Cold resume restores letters and selection only after the canonical response validates the requested run and confirms the same account, locale, riddle and position. It never hydrates answers, evaluation, score, penalties, run snapshots or guess history. Canonical revealed letters replace local letters and repair an uneditable selection. Local input on a provisionally advanced puzzle restores only when the server confirms that successor. Submitted wrong guesses remain cleared and reload never repeats their mutation.

Strict parsing rejects unknown fields, invalid slot data and future guess versions. Input expires logically after thirty minutes, with no background physical deletion timer. Writes are limited to semantic input changes; clock ticks do not extend retention. Exact observed-record checks prevent an older live tab from replacing or removing a newer tab's draft. Optional storage failures leave canonical gameplay operational. Known terminal responses remove the session's observed matching record, and account deletion clears the exact registered storage key. Disposing a mount retains unsent input for recovery.
