# Multiplayer history normalization

Correlated Guess validation already accepts locale-equivalent casing and Unicode composition. Optional canonical history can therefore legitimately record a wrong word using uppercase or decomposed letters. The private ledger previously compared raw strings, rejecting a later normalized spelling of the same word. History equality now uses the existing locale-aware grapheme normalization used by gameplay. Feedback colors and row lengths still match exactly; genuinely different letters still reject.

Two public-session regressions failed before the fix and pass afterward. A one-grapheme question receives a wrong Guess with optional canonical history spelled `À` or decomposed `a` plus grave accent, then resumes with normalized `à`. The first receipt and later refresh both succeed, with one local submission. Four additional ledger cases prove Turkish `I`/`ı` equivalence, English rejection of that pair, ordinary `A`/`a` equivalence and rejection of `a`/`á`. Existing changed-word and changed-color protections remain green. Thirty-nine focused feedback, ledger and recovery tests pass.

Four actual React desktop/mobile browser cases cover uppercase and decomposed receipts, normalized later history, preserved unsent input, no page errors and one local Guess. All 106 retained browser cases pass, for 110 browser cases total. The full client suite passes 1,982 tests across 249 suites, with 105 optional/browser tests and fourteen suites skipped. Portal types pass. All seven configured isolated builds and artifact audits pass: Jest, Facebook, Reddit, YouTube, Netflix, Yahoo and GameSnacks. Logs remain under `artifacts/race-history-normalization/`.

The 119-check manifest retains all prior gates. Repository documentation still reports 68 missing declarations outside this change, and the concurrently edited authentication browser test remains 1,211 equivalent lines against its 1,200 limit.
