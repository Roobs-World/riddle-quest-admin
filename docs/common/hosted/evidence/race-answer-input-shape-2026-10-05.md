# Race answers that native input can complete — 5 October 2026

Fresh race catalog content and newly admitted frozen decks now reject answers containing whitespace-only grapheme slots. This matches the actual native race editor, which discards these slots from committed text and individual cell edits. Before the fix, an answer such as `a b` was admitted as three slots but native input produced `a`, `b`, and an empty slot. Completing it required revealing the space with hints and paying a time penalty.

The matching baseline reproduced 18 unit failures, 24 live/catalog SDK failures and 18 recorded SDK failures. The corrected admission rule handles ordinary spaces, tab, newline, CRLF, nonbreaking space, narrow nonbreaking space, ideographic space, thin space and trim-removable BOM. It checks each original grapheme with the same trim behavior as the editor. A whitespace-plus-combining-mark cluster remains supported because it is not empty after trim; a broad whitespace ban would incorrectly reject it.

The catalog validator reuses bounded segmentation for its existing slot count and existing metadata error. The shared frozen-deck guard rejects incompatible original slots with structured data loss. Existing callers enforce this before new recorded starts, discovery, publication and public/private/bot live match creation. Original answer, clue and fingerprint bytes are preserved. Existing response, guess and historical storage contracts remain unchanged, so accepted attempts can still recover and settle. No new visible copy or locale keys were needed.
