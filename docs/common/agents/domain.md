# Domain documentation

Riddle Quest uses one domain glossary at [docs/common/core/CONTEXT.md](../core/CONTEXT.md). Read and update that file wherever an engineering skill mentions a root `CONTEXT.md` or `GLOSSARY.md`.

Architecture decisions live in [docs/common/architecture/adr/](../architecture/adr/). Read decisions that affect the module before changing its behavior. Keep new decisions in that directory and link them from the relevant module documentation.

Use glossary terms in issue titles, code, tests and design discussions. When a needed concept is missing, record the gap for domain modeling. If a proposal conflicts with an existing decision, name the decision and explain why it needs reconsideration.
