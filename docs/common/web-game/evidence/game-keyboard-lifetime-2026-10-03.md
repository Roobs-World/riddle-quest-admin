# Owned keyboard subscriptions and IME boundaries — 2026-10-03

`useAnswerKeyboard` previously removed and added its window listener whenever an answer callback changed. Single-player submission callbacks change with the draft, and live multiplayer passes callbacks from its current render, so typing and clock updates replaced native subscriptions. Removed callbacks also lacked their own retirement guard if explicitly retained and invoked later. The native software-deletion callback had the same retirement gap.

The physical keyboard hook now retains one listener for each continuously active editor lifetime. A ref supplies current callbacks and eligibility, while cleanup marks that listener retired before native removal. The current listener ignores a newly inactive editor, and old listeners cannot edit after reopening or unmount. `useNativeAnswerBackspace` likewise invalidates its owned callback before removing the native `beforeinput` listener.

Physical shortcuts and `NativeAnswerInput` now ignore key code 229 as well as `isComposing`. Mozilla's [keydown guidance](https://developer.mozilla.org/en-US/docs/Web/API/Element/keydown_event) explains why `isComposing` can be false at a composition boundary while 229 still identifies an IME-handled key. These events belong to the native editor and must not insert answer letters, delete slots or submit prematurely. Ordinary typing, Backspace, native button activation, text-field editing, committed composition and software deletion retain their existing behavior. No visible text, gameplay authority or provider integration changed.
