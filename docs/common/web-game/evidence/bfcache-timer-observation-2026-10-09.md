# Pending-request cache-resume investigation, 9 October 2026

The current durable gameplay journal releases its delivery lease on pagehide and retains pending request IDs. Its existing five-second renewal interval invokes the guarded sendFirst callback; retries remain subject to the original twenty-second resend throttle and committed account/lifetime ownership. There is no direct pageshow delivery callback. Whether an additional callback would improve player latency depends on native timer behavior after an actual cache restoration.

Five browser observations were attempted with a self-contained HTTP fixture and native five-second interval: default Playwright Chromium 153 and Firefox 153; Chromium with the default cache-disable switch removed; Chromium using a native history button rather than automation history navigation; and the active Firefox MCP 157 browser using native link/button interaction. Every return reported pageshow.persisted=false and recreated the script state. These were reloads, not back-forward-cache restorations, so they do not measure cache-resume retry latency. The approximately five-second post-return ticks in the Playwright reports reflect freshly created intervals and are explicitly rejected as evidence of a gameplay delay. The Firefox MCP inline snapshot was sampled before its first tick; its next-tick delay is unknown.

Installed Playwright 1.63.0 coreBundle.js includes --disable-back-forward-cache in its Chromium default switches. Removing that argument did not make this fixture cache eligible. The native-history Chromium navigation exposed a masked notRestoredReasons entry without a specific cause. Neither that entry nor the Firefox observations identifies which policy or automation behavior excluded caching. No immediate pageshow resend change is justified by these observations, and no natural game/provider cache-return behavior is claimed.

Artifacts in `artifacts/bfcache-timer-observation-2026-10-09` retain all probe programs, raw results/logs, source hashes observed after testing and cleanup. Firefox MCP refused an absolute saveTo path outside its own allowed output root; the already returned inline result was archived using ordinary workspace file tools instead. No connector restriction was changed. Its owned tab was closed, the private fixture server exited zero, and its port was confirmed closed. Playwright probes closed their browsers and servers in finally blocks and all handles are terminal. No production or client artifact changed.

The next investigation should either establish true persisted cache restoration in an eligible environment or examine another proven gameplay cost. These measurements rule out using reload-timer values as a basis for a speculative retry optimization.
