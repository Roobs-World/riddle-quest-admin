# Session assembly retention — 5 October 2026

Hosted session assembly no longer keeps every earlier checkout callback, catalog and capability view alive while the provider remains active. The cache retains the current authority assembly. Gameplay stays stable across commerce refreshes, and its gate-specific cache uses weak keys rather than a growing array of past deletion lifetimes.

This removes the scan through every previous commerce configuration when assembling the current session. It also permits obsolete callbacks, wrappers and unused gate lifetimes to be collected. A caller deliberately retaining an older session still owns that session's original callback and gate; eviction neither cancels it nor redirects it to the current callback. Closed gates continue to reject operations.

The fixture imports the actual session factory and fake target adapter. It keeps the provider and current session strongly reachable, stores only `WeakRef` observations of previous callbacks/wrappers/gates, then invokes Chromium's explicit GC after the creation task ends. An uncached control is collected under the same policy. The matrix covers 32, 256 and 1,024 refreshes, with and without gates and deliberately retained callers. Counts measure reachability after controlled GC, not bytes saved or real-device frame performance. Production code uses `WeakMap`; the `WeakRef` and forced-GC machinery belongs only to the verifier.

The original minimal probe fails 9 of 27 checks. Adding the uncached control repeats the same 9 failures among 30 checks; the expanded three-scenario baseline fails 27 of 90. Keeping only the current authority assembly releases checkout callbacks and commerce wrappers, leaving one gate-retention failure. Weak gate keys resolve that remaining failure. The strengthened four-scenario original matrix fails 45 of 132 checks; the final source passes all 132 in each development and production bundling mode. No production instrumentation was added.
