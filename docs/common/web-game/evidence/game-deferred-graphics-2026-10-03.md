# Deferred graphics construction after slow downloads — 2026-10-03

A scene download could begin while the puzzle was visible, then finish after the host paused, multiplayer opened, or the document became hidden. SolarSystem constructed its renderer, geometry, materials and image textures immediately on mount even though its animation controller correctly suppressed draws. A reduced-motion change followed by re-enabling motion during multiplayer had the same effect.

`createDecorativeInitialization` now waits for both the current host pause state and document visibility before constructing optional resources. It owns one pending visibility subscription, constructs once, removes that subscription before construction, guards reentrant refresh, and contains failures from setup or diagnostics. Retirement invalidates retained callbacks. It does not poll or use an animation frame while waiting.

SolarSystem owns this gate through its existing resource lifetime. The pause effect refreshes pending initialization as well as an existing animation controller. Initial construction, normal unmount, partial setup failure and resource cleanup retain their existing owners. Once constructed, later pauses and visibility changes retain the healthy scene and resume its existing frame chain. Reduced motion still removes the child and releases its resources, while the containing failed-import boundary remains intact.

The existing scene configuration, gameplay authority, target SDK isolation and visible copy are unchanged. The native module may still download, parse and evaluate in the background; this change defers scene resource construction and texture-image requests rather than claiming to abort an already-started module load.

## Remaining goal work

The broader goal remains active. Three's internal context-restoration callbacks can still encounter driver failures outside the scene's current initialization owner. Initialization for an unmeasured or zero-sized scene, failure recovery for interactive module loads, and asynchronous gameplay/transport ownership and latency remain candidates for investigation. Initial device capability probing and unavoidable parsing/evaluation of an already-started module are not eliminated by this construction gate.
