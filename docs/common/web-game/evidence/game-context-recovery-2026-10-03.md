# Contained graphics context restoration — 2026-10-03

Three registers its own context-lost, context-restored and context-creation callbacks directly on its canvas. Its restoration handler rebuilds driver state outside the renderer constructor's error guard. A driver exception during that rebuild therefore escaped native event dispatch; the scene's later restoration callback could still mark the context available, while allocations remained live. A removed internal driver callback also had no scene-lifetime guard if explicitly retained and invoked later.

`createDecorativeCanvas` now supplies one scene-owned canvas. It guards context callbacks registered on that instance, maps original listener/capture identity to the installed wrapper, and preserves function receivers, object handlers, loss-event cancellation, ordinary once/abort options and listener removal. Retirement releases original callback references and blocks retained wrappers and add methods. Unrelated events retain native registration behavior. Production browser prototypes are unchanged.

A failed driver callback retires the owned context registrations before reporting or later callbacks in the same dispatch. SolarSystem retires that canvas owner before disposing its graphics resources and identifies restoration failures with the `restore_context` diagnostic. Driver or diagnostic exceptions cannot escape the guarded context callback. Existing independent resource cleanup still runs when renderer disposal fails. Healthy context restoration continues through Three's original implementation, honors host pause, and resumes its existing frame chain.

No gameplay authority, visible text, provider integration or target policy changed. This contains failures rather than asserting a measured frame-rate, CPU, memory-size or input-latency improvement.
