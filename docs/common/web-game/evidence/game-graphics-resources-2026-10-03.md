# Partial graphics construction and resource cleanup — 2026-10-03

SolarSystem previously installed cleanup only after constructing the whole scene. A renderer setup error or a later material/geometry/texture constructor failure could therefore leave earlier allocations without an owner. Collecting resources through the finished scene also could not find geometry created for a mesh whose material constructor subsequently failed. The temporary browser capability probe retained a separate WebGL context until browser collection.

`createDecorativeResources` now owns each returned renderer, geometry, material and texture immediately. It deduplicates shared resources, releases acquisitions in reverse order, runs independent cleanup steps despite individual failures, and reports only the first cleanup failure. Late registrations retire immediately. Its weak identity set does not retain resources after retirement.

SolarSystem uses that owner during setup as well as normal unmount and asynchronous drawing/resize retirement. Initialization failures release partial resources locally. Context release and canvas removal remain independent of renderer disposal. Layout subscriptions, context listeners and the animation controller belong to the same lifetime. Synchronous or asynchronous texture error callbacks retire the optional scene once, while retained callbacks cannot recreate its animation or repeat diagnostics. Renderer context creation failure remains a quiet decorative fallback.

The browser capability probe requests `WEBGL_lose_context` and releases its temporary context when supported. Failure or absence of that optional release does not turn an otherwise available graphics capability into an unavailable one. Existing device, memory, network and reduced-motion eligibility checks remain unchanged. There are no new visible strings or provider integrations.

## Remaining goal work

The goal remains active. Live reduced-motion changes and graphics work behind multiplayer or other opaque surfaces still need attention. This owner covers allocations returned to SolarSystem and callbacks it owns; it cannot recover allocations hidden inside a constructor that throws before returning, abort every internal image-loader operation, or catch Three's internal context-restoration callbacks. Safe document-level recovery for failed interactive modules and other asynchronous gameplay/transport callbacks also remain under investigation.
