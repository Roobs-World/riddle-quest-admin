# Multiplayer delivery-expiry ownership

A scheduler may deliver expiry before returning its resource handle. RacePlay previously cancelled that already-fired handle after a recovery acknowledgment or replacement, and could dispatch the expired command when the recovery observer left its receipt untouched. The three immediate-expiry regression cases fail before the fix; the asynchronous delivery control passes.

The expiry callback now records completion before checking delivery ownership. Scheduling returns without retaining or cancelling a completed timer, and without posting the expired command. An unfinished retired handle is still cancelled. Normal asynchronous sends and recovery-installed replacement commands retain their independent correlation and timer ownership.

Four public-adapter tests cover acknowledged expiry, account replacement during expiry, an observer that does not consume the failed receipt, and asynchronous delivery. All four pass; the combined delivery/timer/loader regression set passes twenty tests. Six real React desktop/mobile cases verify a visible error without any expired Inbox dispatch, successful replacement challenge acknowledgment and its owned account journal, and normal asynchronous Inbox response delivery.

The complete client suite passes 1,865 tests across 229 suites; 103 optional/browser tests and fourteen suites are skipped. All seven configured isolated builds and their configured artifact audits pass: Jest, Facebook, Reddit, YouTube, Netflix, Yahoo and GameSnacks. Retained timer and loader browser gates each pass ten cases. Portal types and file-size limits pass. Logs and the three-failure baseline remain under `artifacts/race-delivery-expiry-ownership/`.
