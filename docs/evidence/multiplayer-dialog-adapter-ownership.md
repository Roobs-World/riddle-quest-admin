# Multiplayer dialog adapter ownership

Replacing a native context/matchmaking or tournament/challenge sharing provider while its dialog promise remained unresolved previously left the replacement controls disabled. The real React harness reproduces thirty-two loading failures across four dialog types, success/failure variants, desktop/mobile and normal/StrictMode. That baseline stops each case at the loading assertion; subsequent late-response assertions are verified after the fix rather than claimed as separately reproduced baseline failures.

Dialogs now carry private provider-selection and exact-delivery identities. Native social, tournament sharing and referral sharing have independent selection lifetimes. Pending UI belongs only to the selected provider. A new provider may open its own dialog while a retired provider's reply remains unresolved. Completion checks both selection and delivery before reporting errors, changing context or clearing loading, so an old reply cannot release another dialog's duplicate guard. Account/entry teardown still invalidates all pending callbacks through the existing generation guard.

Unrelated provider changes retain an owned dialog and its guard. Share dialogs retain their shared duplicate guard while either sharing destination remains current. A still-owned native context completion addresses the latest optional provider-view module, allowing unrelated standings replacement without routing success to a disposed cache. Optional telemetry or error-notification callbacks cannot start sharing after its captured selection has already retired.
