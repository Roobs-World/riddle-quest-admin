# Graphics construction after measured layout — 2026-10-03

SolarSystem previously constructed its renderer, materials, geometry and textures before installing its layout observer. An unmeasured, collapsed or invalid-sized surface could retain a complete scene despite being unable to draw. Host pause and document visibility already delayed first construction, but a measurement arriving after those gates opened was not a prerequisite.

The scene now requests layout observation once, after the host and document permit it, and constructs graphics only after receiving finite positive dimensions. A positive measurement arriving during host pause, document hiding or multiplayer is retained until the puzzle becomes eligible. Pending observation needs no polling frame. The first measurement immediately sizes the renderer before its first draw. A later collapse stops animation while retaining the healthy renderer for recovery. Retirement clears the resize closure and cached measurement before releasing subscriptions/resources, so retained observer callbacks cannot recreate or retain graphics through that closure. Observer construction/registration failures retire pending setup and report one `observe_scene` diagnostic.

Development Strict Mode's discarded effect now retires its pending layout callback before allocating graphics. Re-enabling decoration therefore constructs one current renderer in both React modes; the deferred-initialization fixture was updated to assert that improved behavior. Other hosted graphics fixtures deliver an initial positive measurement automatically, while the dedicated layout fixture holds delivery under explicit control. These harness changes model the new layout prerequisite and do not change production browser APIs.

No visible copy, gameplay authority or provider policy changed. Allocation counts below are tracked resource objects in the fixture, not measured GPU bytes or an FPS/input-latency benchmark.
