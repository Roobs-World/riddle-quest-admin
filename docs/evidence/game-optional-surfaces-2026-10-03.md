# Optional game visual and multiplayer preload recovery — 2026-10-03

A failed SolarSystem module download, or an exception while rendering that decorative subtree, previously reached the page's fatal React boundary. The active puzzle disappeared even though its own state and authority were healthy. Separately, the shared multiplayer preload had no rejection handler or cancellation check before publishing its result. It also ran when a target supplied its own multiplayer component and never used the shared one.

`DecorativeSolarSystem.tsx` now owns the lazy import, Suspense and a boundary limited to that decoration. A failure retires the decoration for the mounted frame's lifetime and reports once through the existing target-owned browser error adapter. The game retains its CSS background, answer editor, session token and normal reward flow. Pause, resume and profile updates cannot restart the failed lazy component. A healthy scene receives the same pause prop as before. The existing capability and idle-loading decisions remain in `GameFrameApp`.

`useGameSurfaces` now catches shared multiplayer preload failures and publishes a prepared component only while its originating effect remains active. A retired effect cannot start preparation through a retained callback or publish a late result or diagnostic. The shared module promise still coalesces requests. `GameFrameApp` requests that preparation only when multiplayer is eligible and a target-owned surface is absent; target-supplied multiplayer remains reachable through the original surface-selection path.

These changes add no visible product text, provider SDK, analytics integration, authority operation or advertising code. Existing locale keys and target adapters remain unchanged.
