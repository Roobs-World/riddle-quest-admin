# Emulator temporary storage isolation, 9 October 2026

Backend package commands that invoke `emulators:exec` now use `scripts/run-isolated-emulators.js`. Each invocation creates a unique temporary directory and passes it as TMPDIR, TMP and TEMP to Firebase Tools and its descendants. Concurrent Storage emulator processes therefore no longer share `/tmp/firebase/storage/blobs`, and hub locator files are separated too. Emulator ports still need distinct configurations; this change does not allocate ports or solve every concurrent emulator conflict.

The launcher forwards SIGINT and SIGTERM to Firebase Tools. Interrupted runs return 130 or 143 even if a child handles termination and exits zero. Successful runs remove only their owned temporary directory after child close. Failed, interrupted or failed-to-spawn runs retain it and print its path: a crashed launcher may leave live emulator workers, so deleting their storage immediately would recreate the failure. No unrelated process or directory is removed by the wrapper.

Three real child-process tests passed under Node 22.23.1: concurrent same-name blob writes stay independent and successful roots disappear; a failing child retains its root; termination reaches the child and returns failure while retaining its files. The new test command is registered as `test:emulator-launcher` and runs before normal and race coverage builds. Both new scripts pass repository ESLint checks.

Two real Firestore/RTDB/Storage runs through this permanent wrapper each passed the two Storage rules tests, including the final runtime logic with temporary-directory audit logging. Subsequent script edits were a CommonJS lint declaration and test-only quote formatting; final process tests and lint were rerun. All twelve allocated ports were confirmed closed, and the final logged owned temporary directory was confirmed absent. Artifacts in `artifacts/emulator-temp-isolation-2026-10-09` retain test logs, emulator results/configurations, cleanup and final source hashes. The source hash record is post-run, not a pre-run freeze proof.

Initial validation scaffolding passed `--test` to a script-path wrapper that does not support Node options, then used an incorrect relative path while adding lint declarations. Both were corrected; final tests invoke the cached Node binary directly. These tooling mistakes changed no game code. No client source or artifact changed and no deployment occurred.
