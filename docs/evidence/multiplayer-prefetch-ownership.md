# Multiplayer category prefetch ownership

The real React host hooks reproduced twelve failures across desktop/mobile and normal/StrictMode rendering. Same-account profile notifications restarted access loading and discarded cached categories. A late access response after switching accounts, including switching away and back before React committed, started a catalog request belonging to the retired account visit. Eight catalog/unmount controls passed before the fix; those controls are not claimed as independently reproduced failures.

Authentication now supplies a capture factory bound to the rendered subscription visit. Its identity remains stable through profile-only notifications and changes when the subscription account visit changes. Existing immediate account checks still read live subscription state. Retained factories cannot capture a later visit, even when its UID matches the original account.

The multiplayer preloader depends on the UID and visit factory rather than the whole user object. It checks captured ownership before requesting access, after access resolves and before accepting categories. Cleanup still cancels work when the locale, race authority or host lifetime changes. Profile updates retain the catalog and no longer issue repeated access/catalog reads; replacing an account visit triggers one fresh access read.

The subsequent cache audit reproduced another twelve failures: a committed replacement frame exposed a cached category from the preceding account visit or locale before passive cleanup cleared it. The harness records committed values in a layout effect, so a later empty frame cannot conceal an earlier stale frame. Categories now carry the exact selection identity that fetched them, and the hook returns an empty catalog whenever that identity differs from the current account visit, locale, authority, deep link or locale policy. It additionally checks immediate account ownership before exposing the cache. Same-account profile updates retain the selection and cached categories.

Forty-eight prefetch browser scenarios now pass, covering profile updates, late access, late categories, batched account round trips, unmount, populated-cache account/locale replacements, sign-out, authority replacement, ineligible locale policy and deep-link changes at 1280px and 390px in normal React and StrictMode. The deep-link control also verifies that resolving new access does not trigger a catalog fetch. The existing twenty profile/reward ownership scenarios pass after changing the account capture factory. The authentication unit test checks that an old factory stays invalid after a round trip and a newly rendered visit can capture ownership.

All 1,651 runnable client tests pass (97 skipped), as do portal types, security and scalability. All seven configured isolated target artifacts build and their exact dependency evidence validates, including all six required browser targets. Shared file-size and documented-declaration checks still fail in the other chat's ongoing subscription/E2E edits. Those files and its full-user-pathway evidence remain untouched.

Logs and source/artifact hashes are recorded in `artifacts/race-prefetch-ownership/verification-held.json`. The new manifest retains previous gates and adds prefetch verification, for 49 checks. It does not claim full stable-source verification or a completed dashboard receipt. The user requested letting the other chat finish; guarded completion remains pending until its edits settle. No Firebase deployment, hosted Jest update or publication occurred in this batch. The multiplayer reliability audit remains active.
