# Retired Activity reads skip deferred authority admission

Activity standings now own a read-scoped cancellation signal. Leaving or closing Activity, committing a provider/account/locale replacement, receiving a new native context invalidation, or reaching the existing eight-second timeout retires that read. The Facebook board adapter checks cancellation before shared context synchronization and again after it settles, before admitting an authenticated standings request. A final signal check sits immediately before the callable, including the microtask boundary between native-context resolution and the outer adapter continuation.

This removes an obsolete request that previously ran after the screen was gone. In the minimized browser reproduction, leaving Activity while context membership was pending still caused one standings request when membership settled; returning to Activity caused another. The final source makes no obsolete request and issues one fresh read on return. Both development and production reproduce two failing assertions against the original source and pass the final source.

Cancellation preserves the shared native membership operation and independent score recording. It does not revoke an already admitted Firebase callable. Consumers of the optional signal retain their original API compatibility, and providers that do not accept it continue to work. Read result acceptance additionally checks committed panel activity and cancellation, preventing retired work from updating presentation before passive cleanup. Timeout and native invalidation abort synchronously; cleanup and old promise settlement cannot clear a newer read's controller.
