# Single-player pagehide checkpoint fix, 9 October 2026

Single-player persistence now saves committed progress on window pagehide as well as hidden-document visibilitychange. A player letter committed immediately before pagehide can therefore reach the existing target checkpoint adapter before passive save effects run. The injected regression commits PIAN → PIANO and fires persisted pagehide from a parent layout effect; the previous hook writes nothing during that event, while the fixed hook writes the full PIANO draft.

Both signals use the same committed state and adapter, account UID/generation comparison, restoration policy and retired-owner guard. Pagehide does not require document visibility to have changed first. Combined visibility/pagehide delivery may save the same checkpoint twice, as existing forced background saves do; it does not replay guesses, purchase hints or grant currency. Both native listeners are removed together, and the layout retirement guard prevents callbacks reaching an unmounted game before passive cleanup. No visible text, locale key, saved protocol field or server behavior changed.
