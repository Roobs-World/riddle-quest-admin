## Implementation

- Existing strict block/report contracts now accept either a legacy `targetUserId` or the caller's own `liveTicketId`, never both. The live resolver follows private tickets and match seats inside the mutation transaction. It checks both run identities, same-provider pool and match bindings, human status, retention deadlines, account existence and permanent deletion guards. No opponent UID or answer is added to the public live view.
- Reporting retains the five fixed categories, no narrative, five unique reports per UTC day and stable reporter/request-ID receipt. A domain-separated hashed ticket binding prevents reusing a report ID for another live match, even against the same human. Legacy recorded-rival requests remain compatible.
- Blocking uses the existing directed block store and waits for bilateral RTDB presence visibility removal before confirming. The UI masks the rival after confirmation. The existing live engine observes either directed block, ends an unfinished pair as a tie without a grant, and excludes subsequent pairing.
- Facebook explicitly opts into the lazy authenticated Firebase callable transport. The default Jest matchmaking adapter retains absent live safety methods. Reddit uses its existing same-origin `/api/game/safety.block` and `/api/game/safety.report` routes; the signed server gateway invokes the shared strict callables and account-operation lease. No new public gateway operation or provider SDK was added.
- The capability-driven UI shows controls only for a human opponent. A synchronous admission lock prevents duplicate clicks; uncertain retries keep the exact selected category, own seat and request ID. Unmounted surfaces reject late outcomes. Existing translations are reused. Scoped layout changes let the expanded panel scroll below the rival without overlap; existing answer-keyboard handling preserves native select and control behavior.
