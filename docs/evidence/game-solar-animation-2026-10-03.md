# Decorative animation lifetime and callback recovery — 2026-10-03

The SolarSystem previously scheduled its next animation frame before checking layout, pause or document visibility. Paused and zero-sized scenes therefore continued waking on every display frame. Rendering exceptions escaped the browser callback and left another frame scheduled. A retained resize callback could also access a disposed renderer.

`createDecorativeAnimation` now owns one frame chain and its visibility subscription. Layout, host pause, document visibility and graphics-context availability determine whether that chain exists. Suspension cancels the request and clears the active timestamp. Resume starts one chain without advancing by suspended wall time. Generation checks reject cancelled callbacks retained across resume or unmount. The existing frame delta clamp and scene motion functions remain in use.

SolarSystem refreshes that controller on host pause, resize and context events. A zero-sized layout skips both resizing and animation. Three retains responsibility for restoring the graphics context. Asynchronous drawing and resize failures retire only this optional scene, remove its canvas, cancel layout/animation subscriptions and report through the existing target-owned error adapter. Cleanup deduplicates shared resources and continues through individual graphics disposal errors. A failed scene stays retired across pause changes for that mounted component's lifetime.

No visible game copy or provider integrations were added. The decoration remains lazy, and all six target artifact audits passed.
