# Deferred decorative context restoration — 2026-10-03

The installed Three WebGLRenderer's `onContextRestore` calls `initGLContext()` immediately. Its scene was already able to suspend drawing, but a native restoration still rebuilt driver state while the host was paused, the document hidden, layout collapsed or multiplayer covering the puzzle. The [WebGL specification](https://registry.khronos.org/webgl/specs/latest/1.0/) requires resource/state recreation after restoration; that work must complete before drawing resumes.

`createDecorativeRestoration` now owns a capture gate on this scene's canvas, installed before the renderer callbacks. A blocked restoration records one pending rebuild and stops the renderer and scene restoration callbacks together. Eligibility refresh replays one canvas restoration dispatch once the actual context has restored and the document, host and layout permit it. Driver rebuilding therefore precedes the scene's availability callback and resumed frame. The installed Three implementation ignores the event payload; replay uses an ordinary Event with the same canvas target. Capture/dispatch ordering is defined by the [DOM standard](https://dom.spec.whatwg.org/).

A newer context loss drops an older pending restore. Retirement drops pending work and removes capture/visibility subscriptions before canvas and graphics cleanup. Visibility refreshes, host pause changes and positive layout updates share the same gate without a polling frame. SolarSystem refreshes restoration before scheduling resumed animation or resizing a pending context. Existing canvas ownership still contains a failed driver callback, removes all context listeners, reports once and retires the optional scene while preserving gameplay. Active restoration continues through the original Three implementation. Production browser prototypes and Three library files are unchanged.

This is specific to the owned decorative canvas and the installed driver's callbacks; it does not promise transparent deferral for arbitrary third-party listeners or preservation of a native event's trusted flag. No visible text, gameplay authority or target integration changed. Evidence establishes avoided driver rebuilds while blocked, not a measured CPU duration, FPS, GPU byte count or input-latency improvement.
