# Avoiding inactive and repeated drawing-buffer resets — 2026-10-03

The installed Three WebGLRenderer's `setSize` assigns both canvas dimensions on every invocation and updates its viewport. SolarSystem called it for every positive observer measurement, even when the integer CSS dimensions were unchanged or drawing was suspended. Subpixel layout changes could therefore cause repeated canvas writes, projection updates and viewport work; changing measurements during pause, hiding, multiplayer or context loss also performed that work immediately.

`createDecorativeSizing` now stores the latest finite positive measurement as integer CSS dimensions. It applies a changed size only when the document, host, layout and graphics context permit it, and records successfully applied dimensions. Repeated equivalent measurements and collapse/recovery at the same size do not reset the buffer. An invalid/latest collapsed measurement cancels an older pending positive size. Inactive changes replace the pending size, so resumption applies only the latest dimensions before the next frame. The owner has no polling frame and contains failed sizing/diagnostics; retirement releases staged dimensions and its visibility listener.

SolarSystem refreshes driver restoration before sizing, and sizing before scheduling resumed animation. Successful context restoration applies a newer staged size before its scene callback starts drawing. Visibility registration order and host pause refresh follow the same sequence. The existing bounded integer buffer/viewport conversion remains in the renderer's actual apply callback. No visible text, gameplay authority or target integration changed.

The counts below come from scripted observer deliveries. They prove avoided operations under those inputs, not a measured production resize frequency, FPS, CPU duration, GPU memory footprint or input-latency improvement.
