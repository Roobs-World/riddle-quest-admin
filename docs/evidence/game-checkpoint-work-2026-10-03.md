# Unchanged gameplay checkpoint work — 2026-10-03

The single-player checkpoint owner now checks the immutable reducer fields used by its saved-game projection before cloning and serializing an unchanged checkpoint. Notice, modal, pause and profile updates keep their existing behavior while avoiding that repeated work. Answer edits, slot changes, confirmed feedback, hint/Continue acknowledgement and pending outcomes still pass through the existing complete-payload fingerprint policy. No save is delayed or batched.

The field check includes the pending guess, hint and coin-spend inputs used to remove speculative progress from a durable snapshot. Browser background signals bypass the check and create a fresh adapter-owned copy. Startup restoration still runs before the check; acknowledged completion still clears progress once. The optimization relies on the existing immutable reducer snapshot contract. Add any future saved-game input to `checkpointFields` alongside the projection change.
