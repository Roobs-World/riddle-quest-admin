# Waiting player-storage snapshots — 2026-10-03

`PlayerProjectionPersistence`, used by Facebook and Reddit, now merges contiguous player updates that have not started executing. Each field keeps the latest accepted value, so draft changes retain independently updated cached profile fields. The in-flight snapshot stays fixed. Every caller in a waiting group shares acknowledgement of the merged snapshot only after the target write and flush succeed. There is no debounce timer or deliberate delay before a ready write.

Preference updates, explicit flush, clear and close/deletion keep their queue positions and separate acknowledgements. Write/flush failures still retain the merged projection for retry. A rejected target ownership gate retires its batch rather than leaving future updates attached to a failed promise.

The actual Facebook artifact exposed an additional queue: `LocalAccountDeletionGate` previously wrapped each save callback before it entered persistence. Facebook now supplies that gate to the persistence owner so it checks ownership when a merged player or preference operation executes. Preference callbacks no longer hold the same gate while awaiting the owner's queue; presence reconciliation retains its own gated operation after preference persistence. This avoids a nested-gate deadlock and lets waiting input reach the merge queue. The gate still rejects account work invalidated by deletion before execution.

Facebook pause now drains the persistence owner captured for that provider session, rather than flushing only the lower-level SDK adapter. This includes accepted app checkpoints waiting behind the current SDK write.
