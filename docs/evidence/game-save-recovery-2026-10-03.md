# Failed Jest save recovery — 2026-10-03

A failed Jest draft, profile projection or completion clear previously remained only in the hook's memory until another accepted update triggered an SDK write. Failed preference patches could also lose an earlier field: a later successful patch wrote only its own field.

`PlayerSaveRecovery` now owns bounded retry scheduling for the Jest write hook. A visible, online view gets three automatic attempts after 1, 2 and 4 seconds. Persistent failure exhausts that episode without polling indefinitely. Online and visible/resume signals grant a fresh bounded episode. Hidden/offline views retain pending recovery without running timers. Disable, account cleanup and effect retirement cancel scheduled work and invalidate asynchronous completions.

The hook marks accepted player projections and merged unacknowledged preference patches dirty until their own SDK flush succeeds. A successful older snapshot cannot clear newer dirty state. Preference retries contain only pending changed fields, preserving unrelated settings or metadata independently changed in SDK storage. The retry adapter drains existing queue positions before deciding whether another write is necessary. It rechecks the captured generation, player ID, enabled state and account-deletion gate after that wait. A healthy save already entered in the SDK cancels redundant recovery when acknowledged.

Recovery uses the existing SDK adapter, queues and durability acknowledgement. It sends no additional guess, completion, reward, identity or purchase request. The SDK promise already entered before retirement still drains; it cannot be cancelled by this hook. Successful progress is never inferred from an optimistic UI or SDK cache value.
