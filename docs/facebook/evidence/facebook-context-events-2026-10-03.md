# Facebook native context changes — 3 October 2026

Facebook now observes `FBInstant.onContextChange` for its authenticated game session. A context selected through Meta’s overlay updates server membership and refreshes an already mounted context board. Returning to solo removes the former membership and clears old rows. Changes outside the race UI also reconcile membership; entering Activity then reads the current context.

The authenticated Meta documentation connector returned [Changing Contexts](https://developers.facebook.com/documentation/games/build/zero-permissions/social-features/changing-contexts), updated 25 March 2026. It describes context creation/switch actions in overlays and the two-callback native context event. The implementation reads the current SDK context through the existing validated adapter; the notification payload does not authorize a context or supply identity.

The bootstrap exposes an optional successful-change subscription only when the SDK method is callable. Its unsubscribe makes retained native callbacks inert, since the documented registration has no unsubscribe return value. One entry-owned coordinator observes the SDK; shared board consumers subscribe to coordinator invalidation without another provider registration. The existing audience/configuration restrictions and SDK-dialog gate remain.

The coordinator invalidates its synchronized snapshot before notifying consumers and serializes membership delivery. Concurrent consumers share the native reconciliation. A newer change retires an older result; membership failures remain retryable. The entry’s active-session/account-operation gate suppresses callbacks and queued writes after retirement. A join already sent to the server cannot be cancelled; retirement prevents a subsequent leave or accepting that result. Existing server account-operation guards remain authoritative.

The board immediately increments its context generation on invalidation. Old responses, errors and timeouts cannot update the new generation before React’s effect cleanup. Existing response-schema and locale validation, read deadline and generic translated recovery remain. No visible text, currency grant, identity exchange, backend endpoint or public matchmaking policy changed. Other targets leave the optional subscription absent.
