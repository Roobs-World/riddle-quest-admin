# Facebook selected-context private challenges — 3 October 2026

The Facebook adapter now prepares a private Live PvP journey after an explicit native context choice. It captures the selected category, content language and native context, then uses the existing server-authoritative `createChallenge` lobby. That path does not enter the public queue or receive the public queue's bot fallback. Ordinary public play, ordinary friend-picker invitations, incoming invitation acceptance and original-opponent rematches retain their existing transports. Context IDs still identify score destinations; this change does not claim server verification of Meta's friendship or group membership graph.

The waiting lobby requires another explicit player action before `FBInstant.updateAsync` posts its invitation to the selected native context. The SDK payload carries only the server-issued opaque challenge handle, a locally rendered PNG and existing translated copy. It uses `CUSTOM`, `IMMEDIATE` and `NO_PUSH`. The English fallback remains English and the current game language uses its corresponding Meta locale identifier. SDK settlement does not mean delivery or recipient acceptance. Successful local sends are deduplicated; failures have no automatic retry. An explicit further player action can retry the same opaque handle, with no exactly-once provider-delivery claim.

The private transport rejects a later native context or language change before joining or sending, including changes during membership delivery or image rendering. A retired intro cannot create a seat after native selection settles. Account retirement, unknown age, disabled multiplayer, missing or unadvertised `updateAsync`, and a missing template independently exclude this optional path. All native surfaces share the existing SDK-instance dialog guard. No new visible text or locale keys are introduced. Jest receives no Facebook SDK or native invitation implementation.

The new browser journey reproduced a coordinator overlap: a native context event started membership synchronization for an Activity consumer, then chooser settlement superseded that operation and returned unavailable to the board. A deterministic coordinator test failed on that exact unavailable result. Chooser and event now share reconciliation. A separate red/green test covers explicit selection on a host without native context events; the chooser notifies mounted consumers only when no event already owns that work.

The target source manifest is [fbapp-config.json](../../packages/portal/targets/facebook/fbapp-config.json). It preserves the previously accepted `RICH_GAMEPLAY` and `NAV_FLOATING` values, leaves orientation dashboard-managed, and declares `custom_update_templates.race_context_challenge.example`. The Facebook mode file selects that template. Vite rejects an enabled template absent from this artifact's manifest, and the artifact audit rejects malformed template declarations.
