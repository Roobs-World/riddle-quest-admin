# HTML5 publishing platform research

Research date: 20 September 2026. Sources are official platform documentation and publisher pages. “Automatable” means the platform documents a supported CLI or API; browser form automation is not treated as a stable publishing API.

## Recommendation

1. **itch.io first.** It is the fastest low-risk release: self-service, no platform SDK or ads, no exclusivity, and subsequent build uploads have an officially supported CI-friendly CLI.
2. **CrazyGames second.** It accepts a plain web build into a limited Basic Launch without platform integration. A separate adapter is needed only if the game earns a Full Launch; monetization then uses CrazyGames ads exclusively.
3. **GamePix, GameDistribution, and GameMonetize after dedicated adapters.** Each is an ad-distribution network and expects its own SDK. Their SDKs and ads must remain isolated from the existing Jest, Facebook, Reddit, YouTube, Netflix, and Yahoo artifacts.
4. **Yandex Games after confirming commercial onboarding is practical for the UK company.** It has strong self-service documentation, but its SDK is mandatory, external purchases are prohibited, and non-Russian developers must complete Yandex Advertising Network contracting to submit for moderation and receive payments.
5. **Build a dedicated Discord Activity.** Discord accepts hosted HTML5 experiences through its Embedded App SDK and does not require distribution exclusivity. Riddle Quest needs an isolated Discord target, application ID, URL mapping, OAuth identity, and Discord-native Premium App products before public discovery and monetization.
6. **Keep Poki on hold.** Poki can consider a non-exclusive flat-fee licence, but its preferred five-year web-exclusive arrangement explicitly includes Discord and YouTube Playables and conflicts with the current release plan.
7. **Add Coolmath Games, Kongregate, and Armor Games to business outreach.** All currently accept HTML5 games and allow a non-exclusive route. Each requires review or account onboarding rather than an unattended publishing API.

## Other portal considered

**Newgrounds** has an open, account-gated [new game project form](https://www.newgrounds.com/projects/games/new), so it may be useful for community exposure. Its public official page does not expose enough current technical, monetization, or automation detail without signing in to rank it above the candidates above. Treat it as a later manual submission rather than promising ads or automated deployment.

## Submission automation boundary

Only itch.io publishes a supported unattended upload mechanism among the reviewed services. For every other portal, automation can prepare the isolated build, archive, checksums, screenshots, descriptions, privacy URL, and dashboard status; browser automation can assist with forms after the owner signs in. Final terms, tax onboarding, contracts, CAPTCHAs, identity checks, and irreversible submission actions remain account-bound portal steps. A portal-specific adapter must be used wherever a portal SDK or ad system is required, preserving the repository's isolation rules.

## Proposed rollout

1. Create an itch.io project and automate later uploads with butler.
2. Prepare and submit a provider-neutral CrazyGames Basic Launch build.
3. Open publisher accounts and inspect current contracts for GamePix and GameDistribution before adding SDK code.
4. Confirm Yandex Advertising Network can contract and pay Roobs World Limited in the UK.
5. Consider GameMonetize after comparing its live contract with GamePix/GameDistribution.
6. Create and deploy an isolated Discord Activity target, then configure its application and URL mapping in the Developer Portal.
7. Keep Poki on hold and consider only a written non-exclusive offer; keep Newgrounds as a later manual submission because official public integration details are limited.
8. Submit non-exclusive pitches to Coolmath Games and Armor Games, and apply for Kongregate developer access.

## Added distribution target: Game Jolt

**Game Jolt** supports browser/HTML5 games through a self-service game page and browser release package. The account owner must create and publish the game, package, and release in the authenticated dashboard; no supported public release CLI was found. The repository therefore produces `build-gamejolt.zip` and a SHA-256 manifest in the all-platform workflow, while the final dashboard upload and publication remain manual. Start at the official [add-game dashboard](https://gamejolt.com/dashboard/games/add). Optional Game Jolt API features must use a future isolated target adapter rather than changing the provider-neutral archive.

## Added review and licensing targets

- **GamePix** explicitly permits an entirely SDK-free game under its current [submission guidelines](https://partners.gamepix.com/guidelines/submission). The workflow now creates `build-gamepix-review.zip`; monetized distribution still requires a separate GamePix adapter and provider review.
- **Addicting Games** accepts a hosted test link through its official [game submission page](https://www.addictinggames.com/about/upload). The workflow retains `build-addictinggames-review.zip` if reviewers request the files.
- **HTMLGames.com** invites HTML5 developers to submit games through its official [developer form](https://html5games.com/Static/Developers). The workflow produces `build-htmlgames-pitch.zip` while commercial and technical terms remain pending.
- **PlayKovo** accepts hosted builds, iframe links, or HTML5 files for manual review through its [developer portal](https://developer.playkovo.com/). The workflow produces `build-playkovo-review.zip`; approval and publication remain manual.

None of these providers documents a supported unattended publishing CLI. GitHub Actions therefore automates reproducible builds, checksums, retention, and dashboard receipts without claiming that a portal accepted or published the game.
