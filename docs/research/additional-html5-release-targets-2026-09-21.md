# Additional HTML5 release targets

Research date: 21 September 2026. This review uses current first-party publisher and developer documentation only. A target is recommended when it accepts an existing browser HTML5 game through a public registration, application, or upload route and does not require an exclusive release. Absence of a published exclusivity requirement is not a substitute for reviewing the authenticated contract before acceptance.

## Recommendation

Add four candidates to the release dashboard and discovery backlog, in this order:

1. **Y8** — direct ZIP or iframe submission, explicit support for games already published elsewhere, and optional platform advertising after approval.
2. **Playgama** — one HTML5 upload can reach Playgama and its distribution network; the developer keeps ownership and grants publishing rights to Playgama.
3. **Amazon Appstore Web App** — a packaged or hosted HTML5 game can be listed for Fire tablets, with an official JavaScript IAP route.
4. **JioGames HTML5** — a public partner portal accepts HTML5 games for Jio set-top boxes and documents advertising and IAP models, subject to account review and SDK access.

These should initially be dashboard candidates rather than claims of publication. Y8 can take the current provider-neutral review build. The other three need a target-specific compatibility or SDK assessment before implementation.

## Integration and automation boundaries

- **Y8:** automate the isolated archive, checksum, screenshots, listing copy, and test report. Upload, studio creation, revenue-share approval, and final publication remain authenticated portal actions; no supported release API or CLI is documented.
- **Playgama:** automate the archive and integration tests. Portal registration, contract acceptance, first upload, moderation, and partner distribution choices remain authenticated actions. Playgama should be recorded as one distributor target, with downstream placements stored as distribution receipts rather than duplicate builds.
- **Amazon:** automate the self-contained package and compatibility tests. Developer enrollment, product creation, content rating, pricing, IAP catalogue, and initial review require Developer Console actions. Do not add Android packaging; use Amazon's documented packaged or hosted web-app route.
- **JioGames:** automate a provider-neutral candidate archive and evidence. SDK integration, ads, IAP, upload, and release cannot be implemented reliably until Jio approves the account and supplies the current documents.

For every new artifact, keep provider SDKs confined to their own target. None of these findings changes the repository rule that Facebook is the only existing target allowed to contain rewarded or interstitial ad code. A new target may receive its own ad adapter only after its provider contract is accepted and its isolated artifact tests prove that the SDK cannot leak into Jest, Reddit, YouTube, Netflix, or Yahoo builds.

## Exclusions from this addition

- **GameArter:** technically supports HTML5, interstitial/rewarded ads, accounts, storage, and IAP, but its current official [HTML5 SDK page](https://www.gamearter.com/developers/html5) says uploads of new games are temporarily paused. Keep it in research, not the active dashboard backlog, until submissions reopen.
- **Samsung Instant Plays 2.0:** Samsung's current [getting-started requirements](https://developer.samsung.com/instant-plays/get-started-in-instant-play.html) require an ARM Android APK, Galaxy Store readiness, and native Samsung SDKs. That conflicts with this repository's browser-only scope and prohibition on Android/native builds.
- **GX.games:** the official publishing paths found are tied to GameMaker/GX.create rather than a documented generic upload route for an existing Vite HTML5 archive. Do not add it until Opera publishes a supported generic browser-game submission route.
- **VK Mini Apps / VK Play:** public official material found during this review was insufficient to verify a current international self-service HTML5 game route, monetization contract, and non-exclusive terms together. Revisit only with current first-party portal documentation.
