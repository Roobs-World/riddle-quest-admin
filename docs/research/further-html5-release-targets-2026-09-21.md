# Further HTML5 release targets

Research date: 21 September 2026. This review uses current first-party publisher and developer sources only. It excludes platforms already present in `config/platform-monetization.json`, native-only stores, paused submission programmes, and routes that publicly require exclusivity. Where a publisher offers several deal structures but does not publish their full terms, the candidate remains contract-gated until Roobs World receives a written non-exclusive offer.

## Recommendation

Add these four candidates to the dashboard discovery backlog:

1. **Famobi** — an established HTML5 publisher with a direct developer submission flow, a large affiliate network, a documented Game API, managed ads, and documented IAP hooks.
2. **GamePush Distribution** — a non-exclusive distribution service covering more than 40 platforms through one integration, with consolidated analytics and payouts.
3. **SOFTGAMES** — a large HTML5 distribution network offering both up-front sponsorship and continuing revenue-share arrangements, subject to contract review.
4. **WGPlayground** — a self-service HTML5 portal and syndication network with explicit non-exclusive terms, managed ads, and SDK-defined IAP support.

These are candidates rather than claims of publication. GamePush and WGPlayground publish explicit non-exclusive routes. Famobi and SOFTGAMES should not move beyond outreach until their written offer confirms that the selected deal is non-exclusive and compatible with the game's existing releases.

## Ads and IAP boundaries

- Each provider must receive a separately built artifact with a target-specific adapter and artifact audit. Famobi, GamePush, SOFTGAMES, and WGPlayground code must never enter Jest, Facebook, Reddit, YouTube, Netflix, or Yahoo builds.
- Provider-managed ad APIs may be implemented only after the relevant account and commercial terms are approved. This does not change the repository rule that Facebook is the only **existing** target permitted to contain rewarded or interstitial ads.
- IAP stays disabled until the provider supplies an authenticated server-verification mechanism. A client success callback is not sufficient evidence for a purchase grant.
- Distributor placements must be modeled as child receipts of the Famobi, GamePush, SOFTGAMES, or WGPlayground agreement. They must not inflate the dashboard's direct-submission count or overwrite an existing direct platform status.
- Any overlap with CrazyGames, GameDistribution, GamePix, Y8, Playgama, Poki, or another tracked destination must be explicitly opted out or recorded as syndication before launch.

## Automation boundary

Automation can prepare a provider-neutral demo URL, isolated ZIP, source ZIP when contractually required, checksums, listing copy, screenshots, icons, compatibility results, SDK-leak audit, and dashboard evidence record. It can also generate provider-specific adapters and test them after official credentials and documentation arrive.

The first registration, tax and payout onboarding, acceptance of publishing/licensing terms, source-code disclosure, SDK credential issuance, destination selection, and final submission remain authenticated or contractual actions. No reviewed provider documents a public deployment API that safely replaces those actions. Publication should only be marked complete from an authenticated approval or live-placement receipt.

## Exclusions reviewed

- **Arkadium:** its current official developer page expressly advertises a required exclusivity period, so it conflicts with the multi-platform release strategy.
- **MarketJS:** the current first-party site is a B2B catalogue for customers buying or embedding MarketJS games. The reviewed pages do not provide a verifiable route for an outside developer to submit an existing game for marketplace publication.
- **GameArter:** excluded in the preceding review because its official developer page says new game uploads are temporarily paused.
- **Azerion portals:** GameDistribution already represents the verified Azerion-owned self-service route in the canonical target list. No separate current first-party submission flow was verified for another Azerion portal that would justify a distinct target rather than a downstream distribution receipt.
