# Reduced-motion viewport fitting after resize — 2026-10-03

Firefox could keep the desktop fitted height after a game was resized to a short screen, reducing the keyboard to about 25 pixels. This follows up the remaining Firefox case in [the preceding short-screen pass](short-viewport-controls-2026-10-03.md).

The controlled trace establishes the cause: both reduced-motion rules assigned a nonzero `0.001ms` transition to every descendant. The fitting wrapper normally has no transition, but its default transition property is `all`. During the hook's synchronous height search, Firefox interpolated from the prior minimum height despite the inline reset to zero. Every candidate in the recorded baseline kept a height of 844 pixels. A computed-style probe reported a nonzero transition, and a sufficiently specific zero-duration CSS probe released the old minimum: natural height became 624 pixels and keys increased from about 25 to 33.6 pixels with the same fitting hook. Priority minimum-height resets, clearing the transform and using offset height had not resolved the problem. The first zero-duration probe had insufficient specificity against the app preference selector; its failed record is retained.

The player preference rule in `styles.foundation.css` and the system preference rule in `styles.guidance.css` now set transition duration and delay to zero. Animation duration and iteration count remain at their existing reduced-motion values. There are no transition-end handlers in the portal source. The fitting hook is byte-for-byte unchanged from the captured baseline. No copy, locale key, authority, input handler, SDK request or persistence behavior changed.
